Concept 01 — Two addresses per device

The IP gets it to the neighbourhood. The MAC gets it to the door.

Every networked device carries a logical address and a physical one. They do different jobs at different layers, and neither works without the other.

IP is logical and routes between networks. MAC is physical and delivers within one.

The IP address is the logical address. It routes packets across different networks, guiding data toward the correct destination network.

The MAC address is the physical address. Once the packet reaches the right network, the MAC delivers it to the correct device on that segment.

Ethernet can only deliver using MAC addresses. So a host that knows a destination IP but not its MAC cannot build a frame at all — it has to find out first.

Your laptop may get 192.168.1.45 from DHCP, but when it talks to your printer it uses the printer's MAC for actual delivery on the local network.

Concept 02 — How ARP works

Shout at everyone. One device answers.

ARP maps an IP address to a MAC address. It does it by broadcasting a question to the whole LAN and waiting for the single device that recognises itself in it.

ARP request goes to FF-FF-FF-FF-FF-FF. The reply comes back to one device only.

PC-A at 192.168.100.10 wants to reach PC-B at 192.168.100.11. Same local network. PC-A builds the IP packet, then needs an Ethernet frame — and for that it needs PC-B's MAC.

It checks its ARP table first, a temporary cache of IP-to-MAC mappings. Nothing there.

So it sends an ARP request to FF-FF-FF-FF-FF-FF, the Ethernet broadcast address. Every device on the segment receives it and has to look at it.

Only PC-B matches the IP being asked about. It sends an ARP reply directly back to PC-A — not a broadcast — giving its MAC.

PC-A caches the mapping and sends the frame. Step through it on the right.

Concept 03 — The ARP table

Cached, but not for long.

Resolving an address every single time would flood the network, so the mapping gets cached. Entries expire quickly — and then the whole process runs again.

Entries are temporary. On Windows 10 they typically last 15 to 45 seconds.

The ARP table is a temporary memory cache of IP-to-MAC mappings. Once a mapping is in there, communication is direct — no broadcast needed.

If a device doesn't communicate again within the ageing window, the entry is removed. Need it again and the whole ARP process repeats.

You can inspect it. arp -a on Windows. show ip arp on Cisco routers. The cache can also be cleared manually.

ARP can affect performance at startup, when many devices power on and resolve addresses at once. That broadcast spike is temporary — once the tables fill, traffic settles.

Concept 04 — Sending to a remote network

The frame goes to the router. The packet goes to the destination.

When the destination is on another network, the destination MAC is not the destination device — it's the router. This is the distinction that trips people up.

Destination IP is the far end. Destination MAC is only ever the next device on this link.

PC-A wants to reach a host on a remote network. It knows it can't get there directly, so it sends the packet to its default gateway.

The IP packet carries the real source and destination IPs. But the Ethernet frame's destination MAC is the router's interface.

The router receives the frame, strips the Ethernet layer, inspects the IP address, works out the next hop, and re-encapsulates the same packet in a brand new frame with new MAC addresses.

MAC addresses are link-specific — they only matter between two directly connected devices. The IP header stays consistent all the way from source to destination, unless NAT modifies it.

Concept 05 — ARP spoofing

ARP believes whatever it's told.

There is no authentication in ARP. Any device can send a reply, and the receiver updates its table without checking. That single design decision is the whole vulnerability.

ARP has no authentication or validation. An unsolicited reply is trusted like any other.

ARP operates on trust. Any device on the network can send an ARP reply, and the recipient updates its ARP table without verifying whether the reply came from the legitimate source.

A malicious actor exploits this by sending fake ARP replies, associating their own MAC address with someone else's IP — most commonly the default gateway.

The attacker announces "I'm the gateway, my MAC is XYZ." Your machine updates its table. Every packet you send toward the internet now goes to the attacker instead of the router.

This is ARP spoofing, also called ARP poisoning. It's the classic route into a man-in-the-middle position.

Concept 06 — IPv6 Neighbour Discovery

IPv6 doesn't use ARP at all.

Same job, different mechanism. Neighbour Discovery uses ICMPv6 and multicast instead of broadcast, so only the device that needs to answer is ever disturbed.

ARP broadcasts to everyone. ND multicasts to a group derived from the target address.

IPv6 replaced ARP with the Neighbour Discovery Protocol, which uses multicast and ICMPv6 messages for address resolution.

To find another device's MAC, an IPv6 device sends a Neighbour Solicitation to a special multicast address derived from the target IP.

The target replies with a Neighbour Advertisement containing its MAC address.

The advantage is that every other device on the segment is left alone. ARP forces all of them to process a broadcast; ND doesn't. That's why it scales better, and why the startup broadcast spike is less of a problem in IPv6.

Concept 07 — What else ND does

Address resolution is only a quarter of the job.

Neighbour Discovery is an all-in-one protocol. Beyond finding MAC addresses it handles routers, prefixes, redirects, and lets a device build its own address without a DHCP server.

Router Discovery, Prefix Discovery, Redirects, and SLAAC — all from one protocol.

Router Discovery lets hosts automatically identify the available routers on the network.

Prefix Discovery lets devices learn the subnet and routing information they need to communicate.

Redirects inform a device when a better default gateway is available for a particular route.

SLAAC — Stateless Address Autoconfiguration — lets devices generate their own IPv6 addresses without relying on a DHCP server at all.

In practice this means plug-and-play connectivity for IoT devices and mobile clients, less manual setup, and fewer address conflicts. It's a large part of why data centres and smart buildings are adopting IPv6.

Concept 08 — Router initial configuration

Mostly the same commands you used on the switch.

Hostname, passwords, banner, domain name, a local user, and the lines. If you configured a switch in Module 1.1, almost all of this will look familiar.

Set the hostname, secure enable mode, warn on the banner, then lock down the console and VTY lines.

hostname Router1 identifies the device. enable secret protects privileged EXEC mode. banner motd displays a warning to anyone connecting.

ip domain-name example.com is needed before you can generate SSH keys.

username admin privilege 15 secret AdminPass123 creates a local account with administrative privileges for SSH login.

On the VTY lines, login local tells them to authenticate against that local user database, and transport input ssh permits SSH only — which disables Telnet.

Finally service password-encryption hides the plaintext passwords in the config.

Concept 09 — Interfaces and show commands

An interface does nothing until you say no shutdown.

A router with two configured interfaces can route between two networks. Configure the address, bring it up, then verify — because an interface that looks configured can still be administratively down.

description, ip address, no shutdown. Then verify with show ip interface brief.

Each interface gets a description, an ip address with subnet mask, and no shutdown to bring it up. Router interfaces start administratively down by default.

Two interfaces on different networks is what makes the box a router: G0/0 on 192.168.1.1/24 for the office LAN, G0/1 on 10.0.0.1/24 for HQ.

Verification splits three ways. Status and config: show running-config for what's live in RAM, show startup-config for what's saved in NVRAM, show version for hardware, software and uptime.

Interfaces: show ip interface brief and show ipv6 interface brief.

Routing: show ip route and show ipv6 route.

Concept 10 — The default gateway

Hosts need one to leave. Switches need one to answer.

A host without a gateway is stuck on its own subnet. A switch without one can't reply to an administrator on a different network — even though it forwards local traffic perfectly.

The gateway must sit in the same subnet as the host, so it can be reached at Layer 2.

The default gateway is normally an IP address on one of the router's interfaces. Hosts send it anything destined outside their own subnet.

A host needs three things configured: its own IP, its subnet mask, and the gateway address — set manually or by DHCP. The gateway must be in the same subnet as the host, otherwise the host can't reach it using MAC addresses.

A Layer 2 switch doesn't need an IP to forward local traffic. But for remote management over SSH it needs an address on the SVI, VLAN 1, plus a default gateway — otherwise replies to an administrator on another subnet never get out.

In IPv6, the gateway is usually learned automatically from ICMPv6 Router Advertisement messages, so no manual configuration is needed on hosts or switches.
