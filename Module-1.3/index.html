Concept 01 — Binary and IPv4

Four octets, eight bits each, thirty-two bits total.

An IPv4 address is binary. Dotted decimal exists only because humans are bad at reading ones and zeros. The device never sees the dots.

32 bits, split into four octets of 8 bits, written as decimal separated by dots.

IPv4 addresses are fundamentally binary — devices rely on that format to identify each other. Binary is efficient for machines and unreadable for people, so we convert.

The 32 bits divide into four groups of 8, called octets. Each octet is written as a decimal number, separated by dots. That's dotted decimal notation: 192.168.11.12.

Each position in an octet has a place value, doubling right to left: 1, 2, 4, 8, 16, 32, 64, 128. Add up the place values wherever there's a 1, and you have the decimal.

That's why the highest possible octet is 255 — all eight bits on — and why 192 is 11000000: 128 plus 64, nothing else.

Concept 02 — Hexadecimal and IPv6

Four bits make one hex digit. Always.

IPv6 is 128 bits. Writing that in binary would be unusable, and in decimal it would be worse. Hexadecimal packs four bits into a single character, which is why IPv6 uses it.

128 bits, eight hextets, four hex digits each. Written x:x:x:x:x:x:x:x.

Hexadecimal is base 16 — the digits 0 to 9 plus the letters A to F. That extra range is what lets one character stand in for four binary bits with no loss of precision.

An IPv6 address is 128 bits against IPv4's 32. Those bits group into eight segments called hextets, each holding four hexadecimal digits.

IPv6 addresses are case-insensitive. Upper or lower case makes no difference to meaning.

To convert decimal to hex, go through binary: turn the number into 8-bit binary, split it into two groups of four from the right, then translate each group into its hex digit.

The same skill reads Ethernet MAC addresses, which are also written in hex.

Concept 03 — What Layer 3 does

Four operations, and not every device performs all four.

Addressing, encapsulation, routing, de-encapsulation. The source host encapsulates. Routers route. The destination host de-encapsulates. Knowing which device does what is the exam question.

The source host encapsulates. The destination host de-encapsulates. Everything between just routes.

Addressing — every end device gets a unique IP address, IPv4 or IPv6, so it can be identified and located.

Encapsulation — the network layer takes data from the transport layer and wraps it in a packet by adding an IP header carrying the source and destination addresses. The source host does this.

Routing — each router along the way reads the destination IP and picks the best path. Every router the packet passes through is a hop.

De-encapsulation — the IP header is checked on arrival. If the destination matches, the header comes off and the data goes up to the transport layer. The destination host does this.

Concept 04 — Layer 3 vs Layer 4

Host-to-host, or process-to-process.

The network layer gets a packet from one machine to another. The transport layer gets data from one program to another. Different jobs, deliberately kept separate.

Network layer: host-to-host. Transport layer: process-to-process.

The transport layer handles process-to-process delivery. TCP living up there is what provides reliability.

The network layer handles host-to-host communication, focused on packet delivery regardless of which applications are involved.

That separation is deliberate. It keeps network services modular and scalable — routing and addressing can change without touching how applications exchange data.

It also explains why IP can afford to be unreliable. Reliability is somebody else's job, one layer up.

Concept 05 — How IP behaves

No connection. No guarantee. No opinion about the wire.

IP is deliberately cheap. It sets nothing up, promises nothing, and doesn't care what medium it's crossing. Everything it doesn't do is done by something else.

Connectionless. Best-effort. Media independent. Three characteristics, and all three are choices.

Connectionless — IP never establishes a dedicated connection before sending. Each packet is treated independently, like posting a letter with no confirmation of receipt.

Best-effort — no guarantee of delivery. Packets can be delayed, dropped, duplicated or arrive out of order. Recovery is handled higher up, by protocols like TCP.

Media independent — IP runs over copper, fibre or wireless without change. That flexibility is why the design has survived.

The trade-off: this low-overhead approach makes IP fast and adaptable, but it only works because other protocols cover for it.

Concept 06 — MTU and fragmentation

IPv4 routers cut packets up. IPv6 routers refuse.

The Maximum Transmission Unit is the biggest packet a link will carry without breaking it apart. What happens when you exceed it is the single clearest difference between the two protocols.

Same oversized packet. IPv4 fragments it. IPv6 makes the sender fix it.

To cross a physical network, the data link layer wraps IP packets into frames suited to that medium. The MTU caps how large a packet can be and still pass through without fragmentation.

In IPv4, a router can fragment a packet that exceeds the next segment's MTU — breaking it into smaller pieces, reassembled at the destination.

In IPv6, routers do not fragment. The sending host is responsible for sizing packets correctly in the first place.

That shift moves work off intermediate devices and cuts overhead, but it makes packet size management the sender's problem.

Concept 07 — The IPv4 header

Five fields worth knowing, and two that never change.

Routers read the header at every hop to validate, identify and deliver the packet. The source and destination addresses stay put the whole journey — unless NAT gets involved.

Source and destination IP stay the same end to end. NAT is the exception.

The IPv4 header is a structured set of fields, encoded in binary, processed by routers and switches along the path.

The ones this module names: source IP address, destination IP address, Internet Header Length, total length, and header checksum.

Routing decisions come from matching the destination IP against the most specific route in the routing table.

NAT maps private IPv4 addresses to public ones. It conserves address space, but it rewrites addresses in flight, adds complexity, and limits true end-to-end communication — which hurts peer-to-peer applications and VoIP.

Concept 08 — IPv4 limits, IPv6 answers

4.3 billion was not enough.

IPv4's problems are all downstream of one thing: it ran out of addresses. NAT was the workaround, and NAT created its own problems. IPv6 removes the original cause.

IPv4: about 4.3 billion addresses. IPv6: about 340 undecillion.

IPv4's three limitations, as the module lists them. Address depletion — roughly 4.3 billion addresses against exponential device growth. No true end-to-end connectivity — NAT masks internal addresses, making direct communication harder. Increased complexity — NAT adds configuration overhead and makes troubleshooting worse.

IPv6's three answers. Expanded address space — 128-bit hierarchical addressing. Enhanced packet handling — a streamlined header with fewer fields, so processing is cheaper. No NAT — enough public addresses that private-to-public mapping becomes unnecessary.

The scale is hard to picture: 340 undecillion has been compared to the number of grains of sand on Earth.

      Concept 09 — Local, remote, loopback

      Three destinations, three completely different actions.

      Before a host sends anything it asks one question: is this address mine, on my network, or somewhere else? The answer decides whether the packet ever reaches a router.

      Local goes via a switch. Remote goes via the default gateway. Loopback never leaves the machine.

      Itself — a host tests its own TCP/IP stack using the loopback address, 127.0.0.1 for IPv4 or ::1 for IPv6.

      Local host — another device on the same segment. Delivered directly, usually through a switch.

      Remote host — a device on a different network. Must be routed through intermediary devices.

      How the decision gets made differs by protocol. IPv4 devices compare the destination against their own address and subnet mask. IPv6 devices rely on local routers advertising the network prefix.

      For anything remote, the packet goes to the default gateway — a router or Layer 3 switch sitting in the same subnet as the host. It forwards traffic beyond the local segment and decides the best path onward. If it's offline or misconfigured, the host is cut off from every other network.

      Concept 10 — Routing tables

      When two routes match, the more specific one wins.

      A router doesn't pick the first match or the best-looking one. It performs a longest prefix match — the entry covering the smallest range of addresses that still contains the destination.

      Longest prefix match. The default route only wins when nothing else does.

      A routing table holds three kinds of entry. Directly connected networks — added automatically when an interface gets an IP address and comes up. Remote networks — beyond the local segment, either configured by an administrator or learned dynamically. Default route — the gateway of last resort, used when nothing else matches, written with all-zero addresses like 0.0.0.0, and configured manually.

      Tables get populated two ways. Static routing is manual and stays put until someone changes it — reliable for small networks, blind to topology changes. Dynamic routing uses protocols that discover networks, update routes, pick efficient paths and reroute around failed links on their own.

      Most real routers use both.

      On a Windows host, route print or netstat -r shows the interface list, the IPv4 route table and the IPv6 route table.
