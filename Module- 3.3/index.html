Concept 01 — Defence-in-depth

No single control stops everything. That is the entire premise.

Layer security so that when one control fails — and one will — another is already standing behind it. Every tool in this module is one ring of that structure.

Multiple layers working together, so that if one fails, others are ready to stop the threat.

Defence-in-depth is a strategic framework that integrates multiple technologies, tools and practices to protect every layer of the IT environment.

The outer rings keep threats away from the network at all. The middle rings control who gets in and what they may do. The inner rings protect the devices themselves and let you recover when something still gets through.

Notice what that implies. A firewall is not a security strategy — it is one ring. The Phantom Intruder in the case study walked past the firewall entirely, because the attack started with a stolen password rather than a blocked port.

Concept 02 — Network hardening

Most breaches start with something nobody bothered to turn off.

Default credentials, unused services, open ports, plaintext protocols. Hardening is unglamorous, free, and the first thing both detectives in this module went looking for.

Strengthen routers, switches, servers and hosts by applying strict security settings.

Routers and switches are the backbone of any network. Left exposed or misconfigured, they become easy targets — and the smallest misconfiguration on one of them can be all an attacker needs.

The essentials: disable unused services and ports to reduce the attack surface, restrict management access to trusted addresses, and enforce strong encrypted administrative credentials.

Cisco AutoSecure applies a baseline of best-practice configurations in one pass — disabling insecure services, enforcing access controls and enabling secure management protocols.

Detective Diaz found devices still using default usernames and passwords straight from the manufacturer. Those are published in the vendor's own documentation. It is the first thing an attacker tries.

    Concept 03 — ASA firewall and SPI

    It doesn't ask what the packet is. It asks whether anyone invited it.

    Stateful packet inspection tracks every connection through the network. A reply to something you requested comes in. Something that starts a conversation from outside does not.

    No invitation, no entry.

    A basic firewall blocks or allows traffic on static rules — this address, that port. The Adaptive Security Appliance goes further, using stateful packet inspection to keep track of every connection flowing through the network.

    If a user inside the company requests a webpage, the ASA recognises the session and lets the response return safely. If an unknown external server tries to initiate contact out of the blue, the ASA shuts the door.

    The firewall is not just checking traffic — it is making sure every packet has a reason to be there, which is what stops outsiders sneaking in or scanning for weaknesses.

    Concept 04 — The DMZ

    Put the public-facing servers somewhere a breach can't spread from.

    Web, mail and DNS servers have to be reachable from the internet. Putting them on the internal network would be reckless. The DMZ is the compromise.

    Even if an attacker breaches a DMZ server, they are trapped in a limited space.

    The Demilitarised Zone is a specially configured subnetwork hosting the organisation's public-facing services — web servers, email gateways, DNS.

    These systems must be accessible from outside. Placing them inside the internal network would be too risky, because a single compromised web server would then sit alongside finance, HR and everything else.

    The DMZ acts as a buffer zone: external access is allowed, but those potentially vulnerable services are isolated from the secure internal environment.

    Breach a DMZ server and the attacker is contained — unable to move freely into sensitive areas of the infrastructure.

    Concept 05 — Traffic filtering

    Three filters, three different questions about the same packet.

    Packet filtering asks where it came from. Application filtering asks what it is. URL filtering asks where it's going. The intruder got past all three by using a website nobody had heard of yet.

    Address and port, then content, then destination reputation.

    Packet filtering blocks or allows traffic based on IP addresses, ports and protocols. Fast, and completely blind to what the traffic actually contains.

    Application filtering analyses the content of traffic flows, identifying and blocking suspicious or unauthorised applications regardless of which port they use.

    URL filtering, delivered through the Web Security Appliance, restricts access to known malicious or suspicious websites — stopping users from downloading malware or reaching phishing pages.

    Here is the uncomfortable part. Despite all three, the attacker cleverly used newly created or lesser-known URLs to slip malware payloads past the filters. A URL filter can only block what it already knows is bad.

    Concept 06 — AAA

    The attack didn't start at the firewall. It started with a password.

    Authentication, Authorisation, Accounting. Who are you, what may you do, and what did you actually do. The third one is how Detective Cheng caught the intruder.

    Authentication verifies. Authorisation permits. Accounting records.

    Authentication verifies who a user is. Authorisation controls what they are allowed to do. Accounting records everything they do while connected.

    The AAA logs are a forensic goldmine — login attempts, successful authentications, session durations, command histories.

    Cheng found a high-privilege administrator account used to access the core network minutes before the attack. Full access: enough to disable firewalls, modify configurations, exfiltrate data.

    One problem. The administrator was off duty. No scheduled task, no remote session, no authorised login expected. The login came from an unfamiliar external IP not associated with any company VPN.

    Either phishing or brute force. Either way the perimeter defences never fired, because as far as the network was concerned, an authorised admin had logged in.

    Concept 07 — VPN and remote access

    Public Wi-Fi is somebody else's network. Assume they're reading.

    A VPN wraps remote traffic in an encrypted tunnel. Intercepting it still works — the interceptor just gets nothing usable.

    Even if someone intercepts the traffic, encryption renders the data unintelligible.

    Virtual Private Networks create encrypted tunnels between remote users and the company network, so sensitive data — passwords, files, emails — travels shielded.

    Remote workers are a genuine exposure. Without secure connections, attackers can exploit insecure remote access points to get back in after you have cleaned up everything else.

    Cheng verified all remote access passed through VPN tunnels, enforcing strong authentication and regularly updating encryption standards.

    The phrasing in the case is worth keeping: securing remote connections sealed the windows the intruder might climb back through. Restoring the network was not enough on its own.

    Concept 08 — IPS, ESA and WSA

    One watches the network. Two watch the two ways users let threats in.

    Almost every breach arrives through email or the web. These three appliances sit on those paths, and the IPS is the one that saw the attack coming days early.

    IPS blocks in real time. ESA filters mail. WSA filters the web.

    The Intrusion Prevention System is the eyes and ears of the network. Unlike passive monitoring, it actively scans for malicious behaviour and blocks it as it happens, matching traffic against known attack signatures.

    Cheng's IPS logs held the clearest evidence in the case: multiple reconnaissance attempts days before the breach. Ping sweeps and port scans, quietly mapping live hosts and open services — exactly the tools from the previous module, seen from the defender's side.

    The Email Security Appliance scans every message for spam, phishing, spoofed addresses and malicious attachments before it reaches an inbox.

    The Web Security Appliance filters web traffic for known malware sites, drive-by downloads and suspicious domains, and enforces safe browsing policies.

    Concept 09 — Backups and patching

    The backup is only real if you validated it before you needed it.

    Offsite, password-protected, and checked for corruption and firmware match. Restoring a compromised backup just reinstalls the breach.

    Backups stored locally can be targeted or corrupted by the same attacker.

    The firm ran regular automated backups of every essential device — routers, firewalls, security appliances. Crucially they were safeguarded offsite on a secure FTP server, protected by strong, regularly updated passwords. Even if the attacker erased configurations on live devices, a clean copy survived elsewhere.

    Restoring is not just copying files back. Cheng ran a backup validation process first, confirming the files were complete, uncorrupted and matched the correct firmware versions — preventing the accidental restoration of compromised or faulty settings.

    Restoration alone stops nothing future. Many intrusions exploit known vulnerabilities in outdated software, so the recovery included applying firmware updates to routers and firewalls, security patches to servers, and updated antivirus definitions across all endpoints.

    Endpoint security protects laptops, desktops and phones with antivirus, host intrusion prevention and secure access policies. Network Access Control ensures only trusted, compliant devices connect at all.
