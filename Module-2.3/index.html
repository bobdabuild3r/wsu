Concept 01 — Why IPv6 exists

It was never only about running out of addresses.

Exhaustion is the headline, but IPv6 also fixed configuration, routing, security and the end-to-end connectivity that NAT destroyed.

4.3 billion addresses became 340 undecillion — that's 3.4 × 10³⁸.

IPv4's pool is exhausted. Every smart device, from fridges to doorbells, needs a unique address, and IPv6 makes that growth scalable.

But the other five reasons matter just as much. SLAAC lets devices generate their own addresses without a DHCP server. Hierarchical addressing and simplified headers improve routing performance and reduce load on network devices.

IPsec was designed in as a fundamental feature rather than bolted on, supporting encryption and authentication by default.

And end-to-end connectivity comes back. NAT broke direct communication in IPv4; removing the need for it helps VoIP, peer-to-peer apps and real-time services.

Concept 02 — Living with both

Three ways to run IPv4 and IPv6 at the same time.

Nobody switched over in a weekend. Dual stack, tunnelling and translation each bridge the gap differently, and each costs you something.

Run both, wrap one inside the other, or convert between them.

Dual stack runs both protocols simultaneously on the same devices. Smoothest path, because nothing needs translating or tunnelling — but it doubles the administrative workload, since two stacks must be configured, secured and managed.

Tunnelling encapsulates IPv6 packets inside IPv4 packets so they can cross an IPv4-only network. Protocols include 6to4, Teredo and ISATAP. It avoids replacing infrastructure, at the cost of complexity, performance overhead and harder troubleshooting.

Translation converts between the two. NAT64 translates the addresses, DNS64 synthesises IPv6 addresses from IPv4 DNS records. Useful for IPv6-only networks reaching legacy content, but it breaks applications that embed IP addresses.

Concept 03 — Format and compression

Two rules shrink an IPv6 address. The second one has a catch.

Drop leading zeros in any segment. Replace consecutive all-zero segments with a double colon — but only once in the whole address, or it becomes ambiguous.

128 bits. Eight 16-bit segments. Four hex digits each, separated by colons.

The preferred format writes all eight segments in full, four hex digits each, even where they start with zeros.

Rule one: leading zeros within a segment can be omitted. 0db8 becomes db8.

Rule two: one or more consecutive all-zero segments can be replaced by a double colon. This can only be used once per address. Twice and there's no way to work out how many zeros belong to each gap.

Prefix length works like CIDR — 2001:db8:abcd:12::/64 means the first 64 bits are the network prefix and the last 64 are the interface ID.

Concept 04 — Address types

Unicast, multicast, anycast. No broadcast at all.

IPv6 deleted broadcast entirely and replaced it with multicast. Unicast then splits into five kinds you can identify by their opening characters.

Read the first characters and you know the type.

Global Unicast (GUA) — publicly routable, like a public IPv4 address. Starts 2000::/3.

Unique Local (ULA) — private, not routable on the global internet. The fc00::/7 block, so addresses beginning fc or fd.

Link-Local — one network segment only, fe80::/10.

Loopback is ::1, the IPv6 equivalent of 127.0.0.1. Unspecified is ::, meaning no address assigned yet.

Multicast starts ff00::/8 — one-to-many, and it replaces IPv4 broadcast. Anycast shares the unicast format and is delivered to the nearest device holding that address.

Concept 05 — Global unicast structure

Half the address is yours to design. The other half identifies the device.

A GUA splits into a routing prefix assigned to your organisation, a subnet ID you control, and a 64-bit interface identifier. That last 64 is why /64 is the standard subnet.

48 bits of global routing prefix, 16 bits of subnet ID, 64 bits of interface ID.

GUAs begin with 2000::/3 — the first three bits are 001. They're globally unique, assigned by internet registries and ISPs, and routable worldwide.

The global routing prefix occupies the first 48 bits and is assigned to an organisation. It routes traffic to the right network globally.

The subnet ID is the next 16 bits, yours to segment however you like. 2¹⁶ = 65,536 subnets from a single /48.

The interface identifier is the final 64 bits, identifying one interface — derived from the MAC address or generated randomly.

Because that split lands on a /64, almost every IPv6 subnet is a /64. Many functions, SLAAC included, depend on it.

Concept 06 — Link-local addresses

Every IPv6 interface gets one automatically, whether you want it or not.

Link-local addresses exist before anything else is configured. Neighbour Discovery runs on them, routers talk to hosts over them, and nothing forwards them past the local link.

fe80::/10 — the first 10 bits are fixed as 1111 1110 10.

Link-local addresses are automatically assigned to every IPv6-enabled interface, used for communication within a single link, and never routed beyond it.

They carry core IPv6 functions: Neighbour Discovery, router communication for advertisements and solicitations, and automatic configuration before any global address exists.

Routers do not forward packets with a link-local source or destination. Because they're only significant on their own link, the same link-local address can appear on different segments without conflict.

To configure one manually on a Cisco interface: ipv6 address FE80::1 link-local.

To verify: show ipv6 interface brief. When pinging a link-local address you must specify the outgoing interface, because the address isn't globally unique.

Concept 07 — RS, RA and SLAAC

The host asks. The router answers. The host builds its own address.

Two ICMPv6 messages start every IPv6 host's life on a network. What happens after the router replies depends on which of three modes the network runs.

RS is ICMPv6 type 133 to ff02::2. RA is type 134 to ff02::1.

A new host sends a Router Solicitation to the all-routers multicast address ff02::2, asking whether any IPv6 routers are present.

A router replies with a Router Advertisement to the all-nodes address ff02::1, carrying the network prefix, the prefix length and the default gateway. Routers also send RAs unprompted, roughly every 200 seconds.

With SLAAC, the host takes that prefix, generates its own 64-bit interface ID, and combines them. Before using the address it runs Duplicate Address Detection — a Neighbour Solicitation to see if anyone answers. Silence means the address is free.

Three modes exist. SLAAC only: no server at all. SLAAC + stateless DHCPv6: host builds its own address, asks a server for DNS. SLAAC + stateful DHCPv6: the server assigns the address too.

The router must have ipv6 unicast-routing enabled to send RAs at all.

    Concept 08 — Building the interface ID

    EUI-64 stretches a 48-bit MAC into 64 bits.

    Split the MAC in half, wedge FFFE into the middle, flip one bit. Predictable and consistent — which is exactly why privacy extensions exist as an alternative.

    Split the MAC, insert FFFE, flip the 7th bit of the first byte.

    A MAC address is 48 bits. The interface ID needs 64. EUI-64 makes up the difference in three steps.

    Split the MAC into two halves. Insert the fixed value FFFE between them. Then flip the 7th bit of the first byte — the Universal/Local bit.

    For 00:1A:2B:3C:4D:5E, the first byte 00000000 becomes 00000010, which is hex 02. The interface ID is 021A:2BFF:FE3C:4D5E.

    This is consistent and predictable, which suits servers and routers. But it exposes the MAC address, so a device can be tracked across different networks.

    Privacy extensions, RFC 4941, solve that by generating a pseudo-random 64-bit interface ID instead, changed periodically. Temporary addresses handle outgoing connections; a stable address handles incoming services.

    Concept 09 — Multicast

    IPv6 has no broadcast. Multicast does that work, more precisely.

    Rather than disturbing every device on the link, IPv6 targets groups. The solicited-node address narrows it further — to the handful of devices that could possibly be the one you want.

    All multicast addresses start ff00::/8 — so they begin with ff.

    Multicast delivers packets to several devices at once without sending a separate unicast copy to each. It's used for routing protocols, service discovery and neighbour discovery.

    Assigned multicast addresses are reserved by IANA for specific protocols. Well-known ones are a subset, universally recognised for common functions.

    The three to memorise: ff02::1 is all IPv6 nodes on the link, ff02::2 is all routers on the link, and ff01::1 is all nodes on the local host.

    A solicited-node multicast address is generated automatically for every unicast or anycast address on an interface. It lets a device send a neighbour solicitation only to devices that might own the target address, instead of everyone. Far more efficient than IPv4's broadcast ARP.

    It powers Duplicate Address Detection and Neighbour Solicitation.

    Concept 10 — ICMP and troubleshooting

    Work outwards. Loopback, gateway, internet, then trace.

    ICMP carries no user data — it only reports what went wrong. Four message types and a fixed order of tests will locate almost any connectivity fault.

    Echo Request and Echo Reply are ping. Time Exceeded is what makes traceroute work.

    Echo Request / Echo Reply — ping sends one and waits for the other. Pinging the loopback, 127.0.0.1 or ::1, tests only the local TCP/IP stack.

    Time Exceeded — the sender sets a TTL, called Hop Limit in IPv6. Each router decrements it, and when it hits zero the router drops the packet and returns Time Exceeded. Traceroute raises the TTL one step at a time and maps the path from the replies.

    Destination Unreachable — no route exists, or a firewall is blocking. ICMPv6 gives more detailed reasons, such as beyond scope of source or administratively prohibited.

    ICMPv6 does far more than report errors — it carries Neighbour Discovery itself, including RS, RA, NS and NA. It is what makes IPv6 work, not just what reports when it doesn't.
